# 阶段一 · 解剖：先把契约写死

## 这一步在防什么

后面七个阶段全部建立在“这个算子的语义是什么”之上。契约没定清楚，基线实现就是在写一个你不确定的函数，测出来的数字也对应不到任何一个明确的语义。

解剖阶段的产物不是代码，是**一页契约**。它要能在不看代码的情况下回答：给我这些输入，输出必须是什么。

## 契约的六个要素

### 1. 形状推导

输出 shape 如何由输入 shape 决定。写出公式，不要举例代替规则。

| 算子 | 形状规则 |
|---|---|
| 逐元素 | 输出 shape = 广播后的输入 shape |
| 行归约（`dim=-1`） | 输入 `[..., D]` → 输出 `[...]` |
| 矩阵乘 | `[M, K] @ [K, N]` → `[M, N]` |
| softmax | 与输入同形 |
| LayerNorm | 与输入同形，统计量按归一化维度算 |

**动态 shape**：如果 shape 在运行时才知道，契约要写明哪些维度允许变化、变化后哪些量需要重算（grid 尺寸、tile 划分、对齐假设都可能失效）。

### 2. dtype 与提升规则

输入 dtype 不同时输出是什么 dtype；累加用什么精度。

一条容易被忽略的规则：**归约和矩阵乘的累加器精度通常高于输入**。fp16 输入用 fp32 累加是常规做法，不是优化——它直接改变数值结果，所以属于契约。

### 3. 布局与 stride

输入是连续的吗？非连续视图怎么处理？输出采用什么布局（NCHW / NHWC / channels-last）？

契约里要写清：**接受非连续输入但内部做 contiguous 拷贝，还是要求调用方保证连续**。这两种选择的性能含义完全不同，不能含糊。

### 4. 广播

哪些维度参与广播、按什么规则对齐。广播规则不是“差不多就行”，它有明确定义（从尾部对齐，长度为 1 的维度拉伸），也有明确定义的**报错条件**。

### 5. 边界语义

这一项最常被跳过，也最容易出故障。至少逐条写清期望值：

| 边界 | 要回答的问题 |
|---|---|
| 非整除长度 | `N=1000`、`block=256` 时，最后 232 个元素由谁处理 |
| 空输入 / size-0 维度 | `sum([0, 5])` 是 `[5]` 个 `0`，不是 `[]` |
| 单元素 | `softmax([x])` 是否为 `[1.0]`；LayerNorm 单元素方差为 `0`，`eps` 放在哪里 |
| 极值 | `±inf`、`NaN` 的传播规则；全负数的 `max` 中性值 |
| 全掩码行 | 注意力中一行全被 mask 时，输出是 `0`、`NaN`，还是报错 |
| 非对齐 | 向量化要求 16 字节对齐时，非对齐尾块走哪条路径 |
| 超大 shape | 元素总数超过 `2^31` 时，索引用什么类型 |

最后一条经常被忽略：`int32` 索引在元素数超过约 21 亿时会溢出，而单个张量到这个规模并不罕见。

### 6. 容差口径

允许的误差是多少、按什么公式算、用什么 dtype 的参考值比较。

关键细节：**参考值要用“真正传进 kernel 的低精度输入”来算**。如果输入在进入 kernel 前已经从 fp32 量化成 fp16，那么用原始 fp32 值算出的参考结果，和 kernel 能做到的最好结果之间本来就有一个差值——那不是 bug，是精度损失。用错参考值会把正常实现判成失败。

## 一个完整例子

`row_softmax`，输入 `[R, D]`，沿 `dim=-1`：

```text
形状     : 输出 [R, D]，与输入同形
dtype    : 输入 fp32 → 输出 fp32；内部用 fp32 计算
布局     : 要求最后一维连续；非连续输入先 contiguous
广播     : 不涉及
边界     :
  - D = 1        → 输出 [1.0]
  - R = 0        → 输出空张量，不报错
  - 含 +inf      → 需要明确策略（当前实现返回 NaN，属于未定义）
  - 全为 -inf    → 需要明确策略，不能默默返回 NaN
  - D = 1000，T = 256 → 末尾 232 个元素必须被覆盖
容差     : atol=2e-6, rtol=1e-5（fp32）
```

这个契约里，`D=1`、`R=0`、全 `-inf` 三条在多数实现里都会被漏掉，直到线上遇到。

## 检查清单

- [ ] 输出 shape 有公式，不是举例
- [ ] 累加精度明确写出
- [ ] 布局要求明确（连续 / 非连续的处理方式）
- [ ] 广播规则与报错条件明确
- [ ] 边界表逐条填了期望值，没有“视情况而定”
- [ ] 容差公式和参考值口径明确
- [ ] 索引类型在超大 shape 下不会溢出

## 常见误区

**只按典型输入写实现。** 整除长度通过、末项为零；`max` 对全负数返回 `0`；5 个相同值的平均值不等于它们——这三类失败的共同点都是契约里没写边界，而不是代码写错了。

**把“能跑”当成“语义定了”。** 一个函数在典型输入上有输出，不等于它的契约完整。
