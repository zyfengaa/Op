# 边界语义

这一页把“边界输入会发生什么”写成可判定的规则。它是[流程阶段一](../../01-workflow/01-anatomy.md)那张边界表的展开。

边界不是“少见情况”。优化引入的 bug 几乎都落在边界上——因为主路径被反复测过，边界没有。

## 空输入与 size-0 维度

“空”有两种，含义完全不同。

**零个元素**：`shape = [0]`，或 `[0, 5]`（第一维为 0）。

**含 size-0 维度的非空形状**：`shape = [3, 0]`。

归约是这里最容易出错的：

~~~text
sum([3, 0], dim=-1)  →  shape [3]，三个元素都是 0（空集求和 = 单位元）
sum([0, 5], dim=-1)  →  shape [0]，没有元素
~~~

**key**：`sum` 对空集的返回值是**单位元 0**，不是报错，也不是 `NaN`。`max` 对空集则没有单位元——必须明确策略（报错，或返回 `-inf`）。

契约里要逐条写清：哪些算子在空输入上报错，哪些返回单位元。

## 单元素

| 算子 | 单元素输入 | 说明 |
|---|---|---|
| softmax | `[1.0]` | 单个元素的 softmax 必然是 1 |
| max / min | 该元素本身 | 无争议 |
| LayerNorm | 输出全 0（归一化后） | 但方差为 0，`eps` 的位置决定结果是否有限 |
| 归约 | 该元素本身 | 无争议 |

**LayerNorm 的单元素是经典陷阱**：方差为 0，除以 `sqrt(0 + eps)`。`eps` 放在 `sqrt` 里面还是外面，结果不同。这不是细节，是契约。

## 极值与特殊值

| 输入 | 要回答的问题 |
|---|---|
| `+inf` 参与 `max` | 返回 `inf`（合理） |
| 全为 `-inf` 的行做 softmax | `exp(-inf - (-inf)) = exp(nan) = nan`。需要明确策略 |
| `NaN` 参与 `max` | 传导 `NaN`？还是忽略？两种约定都有，必须选一个 |
| 全负数的 `max` 归约 | 中性值若用 `0` 初始化，会返回 `0` 而不是真正的最大负数 |
| 极大值相加溢出 | fp16 下 `30000 + 30000` 溢出为 `inf` |

**“全负数的 max”是本仓故障题 RD02**：`max` 的中性值用 0 初始化时，全负输入的答案会错成 0。归一化维度上做归约时，这个 bug 会静默地改变输出。

## 非整除长度

~~~text
N = 1000，block = 256
ceil(1000 / 256) = 4 个块
前 3 个块处理 768 个，最后一个块只有 232 个有效
~~~

需要明确：

- 越界线程**完全不参与**（不是读到越界数据再丢弃）
- 归约时越界线程贡献的是**单位元**，不是 0——对 `sum` 是 0，对 `max` 是 `-inf`

**“越界线程贡献 0”是本仓故障题 RD03 和 GM01 的主题**：对 `sum` 恰好正确，对 `max`/`min` 会静默出错。同一个写法在一种归约上对、在另一种上错，这就是边界必须逐条写、不能类比的原因。

## 非连续与非对齐

| 情况 | 要明确 |
|---|---|
| 输入是非连续视图（stride 不为 1） | 内部 contiguous 拷贝，还是要求调用方保证连续 |
| 向量化要求 16 字节对齐 | 非对齐的行尾走哪条路径 |
| 转置后的输入 | 访问模式改变，性能假设可能失效 |

**对齐是性能契约**：如果 kernel 假设 `K % 4 == 0`，那么 `K = 41` 时必须走尾块路径或报错，不能默默读错。

## 超大 shape

元素总数超过 `2^31` 时，`int32` 索引会溢出。

~~~text
2^31 ≈ 21.47 亿个元素
fp32 下约等于 8.6 GB 的张量
~~~

这在推理场景并不罕见。契约里要明确索引用 `int64` 还是需要分段。

## 检查清单

- [ ] 空输入：报错还是返回单位元，逐算子写明
- [ ] size-0 维度：输出 shape 正确
- [ ] 单元素：每个算子的期望值已写出
- [ ] `max`/`min` 的中性值用 `-inf`/`+inf`，不是 `0`
- [ ] 非整除：越界线程贡献单位元，且单位元按归约类型区分
- [ ] `NaN` 的传导约定已选定
- [ ] 非连续输入的处理方式已明确
- [ ] 向量化对齐假设已写明，且有尾块路径
- [ ] 索引类型在超大 shape 下不溢出

## 常见误区

**对空集返回 `NaN`。** `sum` 应该返回 0。

**用 `0` 当 `max` 的中性值。** 全负数时静默出错。

**越界线程“读到越界数据”而不是“不参与”。** 前者是未定义行为。

**把非整除当成罕见情况。** 它是最常见的边界。

**在一种归约上验证过的写法直接套用到另一种。** `sum` 和 `max` 的单位元不同。
