# dtype 与精度

算子的数值行为由 dtype 决定。这一页回答：什么时候 dtype 会改变结果，以及怎么处理。

## 浮点数不是实数

三个必须记住的事实：

**1. 加法不满足结合律。**

~~~text
(1e20 + 1.0) + (-1e20) = 0.0
1e20 + (1.0 + (-1e20)) = 1.0
~~~

同样的三个数，换个相加顺序，结果不同。所以**归约的顺序是契约的一部分**，不是实现细节。

**2. 可表示的数不是均匀分布的。** 越靠近 0 越密，越远离 0 越稀。fp32 有约 7 位十进制有效数字；`1e20 + 1.0` 里那个 `1.0` 直接消失了。

**3. 有特殊值。** `+inf`、`-inf`、`NaN`。它们参与运算的规则和普通数不同（`NaN` 与任何数比较都为 false，包括和它自己）。

## dtype 谱系

| dtype | 位宽 | 指数位 | 尾数位 | 典型用途 |
|---|---|---|---|---|
| fp64 | 64 | 11 | 52 | 参考实现、数值验证 |
| fp32 | 32 | 8 | 23 | 默认训练/推理精度 |
| tf32 | 19 | 8 | 10 | 矩阵乘的折中（tensor core） |
| bf16 | 16 | 8 | 7 | 训练，动态范围同 fp32，精度低 |
| fp16 | 16 | 5 | 10 | 推理，动态范围小，易溢出 |
| fp8 (e4m3/e5m2) | 8 | 4/5 | 3/2 | 推理加速，需配合缩放 |

**bf16 和 fp16 的关键区别在指数位**：bf16 的 8 位指数与 fp32 相同，所以动态范围不缩水，代价是尾数只有 7 位；fp16 尾数有 10 位更精确，但指数只有 5 位，范围小得多，容易上下溢出。

选哪个取决于你的数值范围，不是“哪个更新”。

## 累加精度：最常被忽略的一条

**输入 dtype 和累加 dtype 通常不同。** 这不是优化，是契约。

~~~text
fp16 输入，fp16 累加 → 累加 1000 个值后误差显著累积，可能溢出
fp16 输入，fp32 累加 → 常见做法，误差可控
~~~

原因：累加是有顺序的重复加法，误差会累积；而累加一个长向量需要的动态范围，往往超过低位宽 dtype 能提供的。

**结论**：写算子契约时必须写明累加器 dtype。它直接改变输出，属于语义，不属于性能调优。

## 误差从哪来

| 来源 | 说明 |
|---|---|
| 表示误差 | 输入本身就无法被精确表示 |
| 舍入误差 | 每次运算结果被舍入到最近的表示 |
| 累积误差 | 长归约中舍入误差不断叠加 |
| 抵消误差 | 两个接近的大数相减，有效位大量丢失 |
| 顺序误差 | 换个相加顺序，结果不同 |

**抵消误差**是 softmax、LayerNorm 这类算子做数值稳定的根本原因：`exp(x - max)` 而不是 `exp(x)`，是为了避免 `exp` 溢出，也是为了避免大数相减的抵消。

## 参考值该用什么精度算

一个常见错误：用原始 fp32 输入，算出 fp64 的参考值，然后指责 fp16 的 kernel 不准。

正确的做法是**用真正传进 kernel 的低精度输入值**来算参考：

~~~text
错误：reference = fp64(原始 fp32 输入)
正确：reference = fp64(fp16(原始 fp32 输入))
~~~

因为输入在进入 kernel 前已经从 fp32 量化成 fp16，那一步的精度损失**不是 kernel 的错**。用错的参考值，会把正常实现判成失败。

## 容差怎么定

| 比较对象 | 常用容差 |
|---|---|
| fp32 vs fp32 | `atol=1e-5`, `rtol=1e-5` |
| fp16 vs fp32 参考 | `atol=1e-3`, `rtol=1e-2` |
| 归约类（长 K） | 容差随 K 增大而放宽，误差随 `sqrt(K)` 量级增长 |

**容差不能随结果调。** 发现对不上就放宽容差，是把 bug 变成“通过”。

## 检查清单

- [ ] 输入输出 dtype 明确
- [ ] **累加器 dtype 明确写出**
- [ ] 归约顺序是否属于契约，已说明
- [ ] 容差与 dtype 匹配
- [ ] 参考值用真正传入 kernel 的精度计算
- [ ] 极值（`inf`、`NaN`、下溢）行为已定义

## 常见误区

**以为 fp16 和 bf16 可以互换。** 动态范围和精度是两个方向，选错会导致溢出或精度不足。

**用 fp32 参考值去卡 fp16 kernel。** 见上。

**假设归约顺序无关。** 在浮点下它有关，而且会影响可复现性。

**把 `eps` 当成可以随便放的小数。** 它的位置和大小影响数值行为，属于契约。
