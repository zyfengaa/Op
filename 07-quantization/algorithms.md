# 量化算法：映射、粒度与校准

这一页回答：fp32 的数怎么变成 int8/fp8/int4 的整数，scale 和 zero_point 从哪来，粒度怎么选，PTQ 和 QAT 各自在做什么。量化 kernel 的数据路径见 [kernels.md](kernels.md)，精度代价怎么量见 [evaluation.md](evaluation.md)。

## 仿射量化：一条直线

最常用的量化是**仿射（affine）量化**，本质是找一条把浮点区间映到整数区间的直线：

~~~text
量化：      q = clamp(round(x / scale) + zero_point, qmin, qmax)
反量化：    x ≈ scale × (q − zero_point)
~~~

其中 `scale` 是浮点步长（一个整数台阶代表多大的浮点值），`zero_point` 是浮点 0 对应的整数值。

- **scale 决定分辨率**：`scale` 越小，能区分的浮点值越细。均匀量化下，量化误差的**绝对**上界就是半个步长：`|x − x̂| ≤ scale/2`。这是理论界，实际误差要看分布，见 [evaluation.md](evaluation.md)。
- **zero_point 决定对齐**：把浮点区间 `[min, max]` 平移，使浮点 0 能被**精确**表示成整数。浮点 0 能精确表示很重要——补零（padding）、ReLU 的零、mask 的零都必须保持为 0。

### scale 怎么算

给定一个张量的观测范围 `[min_x, max_x]` 和整数范围 `[qmin, qmax]`：

~~~text
非对称（zero_point 非 0）：
    scale    = (max_x − min_x) / (qmax − qmin)
    zero_point = round(qmin − min_x / scale)，再 clamp 到 [qmin, qmax]

对称（zero_point = 0）：
    scale = max(|min_x|, |max_x|) / qmax
~~~

整数范围由量化位宽决定：int8 有符号是 `[-128, 127]`，无符号是 `[0, 255]`；int4 有符号是 `[-8, 7]`。

## 对称 vs 非对称

| 维度 | 对称 | 非对称 |
|---|---|---|
| zero_point | 恒为 0 | 可为任意整数 |
| 整数区间 | 关于 0 对称，如 `[-127, 127]` | 贴合 `[min, max]`，如 `[0, 255]` |
| 额外计算 | 无 | 反量化要减 zero_point；GEMM 里会产生额外交叉项 |
| 零的表示 | 精确 | 精确（这是 zero_point 的用途） |
| 适合 | 权重（分布近似以 0 为中心） | 激活（ReLU 后非负、分布有偏） |
| 常见组合 | 权重对称 int8 | 激活非对称 uint8 |

**判据**：看数据是否以 0 为中心且大致对称。权重量化通常用对称 int8；激活经过 ReLU 后全非负，用非对称 uint8 能少浪费一半的量化级。但非对称在 int8 GEMM 里会引入 zero_point 的补偿项，kernel 实现更复杂——如果激活本身接近对称（如经过 LayerNorm），直接用对称更简单。

## 粒度：精度与开销的权衡

同一个张量，用几个 scale 去量化，就是粒度。

| 粒度 | scale/zero_point 数量 | 精度 | 开销 | 典型用途 |
|---|---|---|---|---|
| per-tensor | 整个张量 1 组 | 最低 | 最低（1 个寄存器，直接广播） | 激活、对精度不敏感的张量 |
| per-channel | 每个输出通道 1 组（权重按行） | 中 | 低（epilogue 按列加载） | 权重 int8，最常见 |
| per-group | 每 G 个元素 1 组（沿 K 方向切） | 高 | 中高（组粒度影响访存） | 权重 int4，G 常取 32/64/128 |

为什么权重必须细化粒度：一个权重矩阵的不同输出通道，数值范围可能差几十倍。per-tensor 会被最大的那个通道撑大 scale，导致小通道的量化级几乎全被浪费。**观察**：per-channel 相比 per-tensor 常常是“几乎免费地”拿回大部分精度。**假设**：具体收益要在你的模型上实测，不同层差异很大。

group 粒度对 kernel 的影响见 [kernels.md](kernels.md)——组大小必须和 K 方向的 tile 对齐，否则访存会成为瓶颈。

## PTQ：训练后量化

PTQ（Post-Training Quantization）不改权重、不重训练，直接对已经训练好的模型做量化。流程：

~~~text
1. 准备校准数据（有代表性的输入样本，通常几十到几百条）
2. 前向跑校准数据，统计每层权重/激活的 [min, max] 或分布直方图
3. 由统计量算每层的 scale / zero_point
4. 用这些参数量化权重，激活在运行时按同一套参数量化
5. 评估精度（见 evaluation.md）
~~~

### 校准是 PTQ 的成败点

**校准数据的分布必须和真实推理分布一致**，这不是可选项：

- 激活的 `[min, max]` 完全由实际输入决定。校准数据如果全是短文本，长文本推理时激活超出校准范围的尾部就会被 clamp，误差骤增。
- 激活分布有长尾和离群通道。用“最大值”定 scale 会被少数离群点撑大，牺牲大多数值的分辨率；用直方图/KL 之类的分位数定 scale 可以缓解，但同样依赖校准集的代表性。
- 校准集太小 → 统计量不稳；太大 → 浪费时间。经验起点是每层几百条，具体按任务定。

**一句纪律**：校准集不能只用“随便几条样本”，也不能用了训练集就以为没问题——要检查它覆盖了真实推理的长度、领域和 batch 形态。

## QAT：量化感知训练

QAT（Quantization-Aware Training）在训练时**模拟**量化误差，让权重去适应它。

核心矛盾：`round()` 的导数几乎处处为 0，梯度无法穿过它反传。解决办法是 **STE（straight-through estimator，直通估计器）**：前向照常量化（引入真实误差），反向时**假装 `round()` 是恒等函数**，把梯度原样传过去。

~~~text
前向：  q = round(x / scale)        ← 引入量化误差
反向：  ∂q/∂x = 1                   ← 假装量化不存在
~~~

**直观解释**：量化误差是不可导的台阶，但我们知道它大体不改变信号方向，所以反向时忽略台阶、只让它把梯度“透过去”。权重因此会在训练中朝着“即使被量化也不掉点”的方向调整。

QAT 的定位：PTQ 精度不达标时的下一步；代价是要重训练。通常先做 PTQ，只在掉点不可接受时才上 QAT。

常见变体（只给定位）：

| 方法 | 一句话定位 | 适用 |
|---|---|---|
| LSQ | 把 scale 也作为可学习参数，和权重一起训练 | QAT 里让量化步长自适应 |
| QAT + 蒸馏 | 用 fp32 教师模型监督量化学生 | 掉点严重、预算充足 |

## 常见 PTQ 方法的定位

这三种都是 PTQ（部分需少量微调），解决的是“直接量化掉点太多”：

| 方法 | 一句话定位 | 何时选 |
|---|---|---|
| GPTQ | 逐层做**误差补偿**：量化一列，用剩余未量化的权重去补这次量化造成的输出误差 | 权重 only、int4 及以下，要榨干位宽 |
| AWQ | 按**激活的重要性**保护权重通道：激活大的通道量化误差影响大，就少动或按重要性缩放 | 权重 only，尤其是激活有显著离群通道的 LLM |
| SmoothQuant | 把激活的量化**难度迁移到权重**：用通道级缩放让激活变平滑、权重变难一点，两边都可量化 | 激活和权重都要 int8 的 W8A8 |

**不要混淆适用面**：GPTQ/AWQ 主要解决**权重**的 int4，激活仍较高精度（W4A16）；SmoothQuant 解决的是**激活也量化**时的离群问题（W8A8）。选错方法会得到“实现了但没解决问题”的结果。

## 常见误区

**把 `scale` 当成“随便定一个缩放”。** 它由数据范围决定，错了直接掉点。校准时用的分布必须和推理一致。

**以为 per-tensor 够用。** 权重通道间范围差异大时，per-tensor 会牺牲大量精度。权重至少要 per-channel。

**在对称与非对称之间凭感觉选。** 判据是“分布是否以 0 为中心”以及“kernel 能否承担 zero_point 的补偿项”，不是习惯。

**以为 PTQ 一定够用、或 QAT 一定更好。** 正确顺序是先 PTQ、评估，掉点不可接受再考虑 QAT，成本差一个量级。

**混淆 GPTQ/AWQ/SmoothQuant 的问题域。** 见上表：权重 int4 用 GPTQ/AWQ，激活也要量化用 SmoothQuant。

**校准集采样偏了还怪算法。** 激活范围由校准数据决定；分布不匹配时，精度下降是校准的问题，不是量化算法的问题。
