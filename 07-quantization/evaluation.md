# 精度评估：用实测数据证明量化没坏

量化一定掉精度。这一页回答两件事：怎么量出掉多少，以及怎么报告才可信。核心纪律是**用实际数据评估，不用理论界代替证据**。

## 为什么不能只看理论误差上界

均匀量化有一条干净的理论界：最大绝对误差是半个量化步长，`|x − x̂| ≤ scale/2`。它有用，但**不能当作精度结论**，原因：

- 它只约束**单个元素**。算子输出是成百上千个元素的组合，误差在归约、激活、层间会放大或抵消。
- 它假设输入落在量化范围内。真实激活有长尾和离群通道，超出范围的部分被 clamp，误差远超步长一半。
- 它不说**端到端指标**会掉多少点。困惑度、准确率、BLEU 与单算子误差不是简单函数关系。

**结论**：理论界用来判断“会不会差得太离谱”，实际数值靠数据。任何只给理论界的量化收益报告都不完整。

## 评估什么

两个层次都要评，缺一不可。

### 单算子：输出与 fp32 参考的误差

用同一份**量化后的输入**，分别跑量化 kernel 和 fp32 参考实现，比较输出。

| 被测 / 参考 | atol 起点 | rtol 起点 | 说明 |
|---|---|---|---|
| fp32 vs fp32 | 1e-5 | 1e-5 | 常规浮点口径 |
| fp16 vs fp32 | 1e-3 | 1e-2 | 与 [dtype-and-precision.md](../02-foundations/contracts/dtype-and-precision.md) 一致 |
| int8 vs fp32 | 1e-2 | 1e-1 | 比 fp16 宽约一个数量级，**具体按任务定** |

**注意**：上表是**起点，不是标准**。int8 的容差要结合任务——图像分类能容忍较宽，语言模型 logits 往往要更严。容差定好后**不能随结果调**；发现对不上就放宽容差，等于把 bug 变成“通过”。见 [dtype-and-precision.md](../02-foundations/contracts/dtype-and-precision.md)。

### 端到端：任务指标的变化

单算子误差合格，不代表模型指标不掉。必须测：

| 任务 | 指标 | 关注的量 |
|---|---|---|
| 语言模型 | 困惑度（perplexity） | 相对上升百分比 |
| 分类 | top-1 / top-5 准确率 | 绝对下降百分点 |
| 翻译 / 生成 | BLEU / ROUGE 等 | 绝对下降 |
| 检测 / 分割 | mAP / mIoU | 绝对下降 |

**观察**：单算子误差和端到端指标弱相关——某些层算子误差大但指标无感，另一些层算子误差小却掉点明显。
**假设**：掉点主要来自少数敏感层，需要逐层分析定位（见下），不能靠平均误差推断。

## 参考值的口径：必须用真正的低精度输入

这是与 [dtype-and-precision.md](../02-foundations/contracts/dtype-and-precision.md) 完全一致的一条，也是量化评估里最常被违反的：

~~~text
错误：reference = fp32(原始 fp32 输入)          ← 把输入量化本身的损失算成了 kernel 的错
正确：reference = fp32(真正传给 kernel 的量化输入)
~~~

具体到量化：

- **权重量化**：参考里的权重必须是 `dequant(W_q)`，不是原始 fp32 权重。两者差的就是量化误差，那部分**不是 kernel 的 bug**。
- **激活量化**：参考里的激活必须是同样的量化/反量化结果。校准时的 `[min,max]`、zero_point 都要一致。
- **比较发生在同一个域**：把量化 kernel 的输出和参考都反量化到 fp32（或 fp16）再比，不要在整数域和浮点域之间直接比。

用错的参考，会把正常的量化损失判成实现错误，让人去修一个并不存在的 bug；反过来，它也会掩盖真正的问题——因为容差被这层额外误差占满了。

## 误差随规模怎么变

不要假设“K 变大误差会自动抵消”。要分清两个来源：

| 来源 | 随 K 的行为 | 量级 |
|---|---|---|
| 输入量化误差 | 不抵消，最坏随 K 线性增长 | 见下 |
| int32 整数累加 | 无舍入，K 内精确 | 溢出前为零 |
| fp16 浮点累加 | 随机游走约 sqrt(K)，最坏线性 | ulp/2 每步 |

输入量化误差的具体账：

~~~text
dot = Σ_{k=1..K} a_k · b_k
量化后绝对误差 = Σ (Δa_k · b_k + a_k · Δb_k)

均匀量化下 |Δa_k| ≤ scale_a/2，|Δb_k| ≤ scale_b/2
最坏情况（误差同号、全部同向叠加）：
  |Δdot| ≤ (K/2) · (scale_a · mean|b| + scale_b · mean|a|)

即绝对误差随 K 线性增长；它不会因为项数多而互相抵消。
~~~

**相对**误差还要看输出本身：如果 `dot` 因为正负项互相抵消而接近 0，而各项量级不小，那么**绝对误差不变、相对误差爆炸**。softmax 分母、残差、注意力输出都容易出现这种结构，评估时必须同时看 atol 和 rtol，不能只看一个。

**结论**：单算子容差要随 K 和输出量级调整，评估用例要包含“长 K”和“输出接近抵消”两类形状，不能只测一个典型尺寸。这与 [dtype-and-precision.md](../02-foundations/contracts/dtype-and-precision.md) 里“归约类容差随 K 放宽”是同一条，只是量化条件下的放大更明显。

## 逐层敏感度分析

不是所有层对量化同样敏感。定位敏感层的做法是**控制变量**：

~~~text
1. 全 fp32 跑端到端，记录指标基线
2. 只量化第 L 层，其余保持 fp32，重测指标
3. Δ_L = 指标(只量化 L) − 基线
4. 对每层重复，得到敏感度排序
5. 敏感层保留高精度或细化粒度（per-channel / per-group），其余量化
6. 用最终混合方案再跑一次端到端，验证
~~~

**注意**：逐层敏感度是**筛查**，不是可加的预测。层间有相互补偿，把各层单独测出的 Δ 相加不等于一起量化后的 Δ。所以第 6 步的最终验证不可省。代价高时可以只对“权重范围异常大”“激活离群通道多”的层做逐层分析，而不是全量扫。

## 报告纪律：收益和代价一起报

**只报“快了 2 倍”不报精度变化，结论不完整。**

一份可信的量化报告至少包含：

| 项 | 内容 |
|---|---|
| 收益 | 加速比 / 吞吐提升，按 [measurement.md](../04-performance/measurement.md) 的口径给中位数和区间 |
| 精度代价 | 单算子误差 + 端到端指标的绝对变化 |
| 评估数据 | 用哪个数据集、多少样本、和训练集是否重叠 |
| 参考值口径 | 参考是否用低精度输入计算 |
| 结论类型 | 区分“观察”（实测到的数字）与“假设”（对原因的解释） |

性能部分中位数与区间重叠时，结论是“证据不足”，见 [阶段八](../01-workflow/08-verify.md) 与 [阶段三](../01-workflow/03-measure.md)。精度部分同理：指标差异落在评估噪声内时，不能宣布“无损失”。

## 常见误区

**拿原始 fp32 输入算参考，然后骂 kernel 不准。** 见上，会把量化损失误判为实现 bug。

**用理论误差上界代替实测。** 上界假设输入在范围内、误差独立，真实分布不满足。

**只看单算子误差，不看端到端。** 平均误差小可能仍掉点；某些层误差大却无感。

**用训练集或没有代表性的数据评估。** 会高估精度（数据见过），也掩盖推理分布下的真实损失。

**只报速度不报精度。** 结论不完整，无法判断这次量化是否可用。

**假设 K 增大误差自动抵消。** 输入量化误差最坏随 K 线性增长；输出接近抵消时相对误差爆炸。

**把逐层敏感度直接相加。** 层间有补偿，逐层是筛查，最终必须端到端验证。

**容差随结果调。** 对不上就放宽容差，是把 bug 变成“通过”。
