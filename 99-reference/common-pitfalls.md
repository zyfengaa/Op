# 跨算子常见错误清单

按“症状”组织，不按算子。每一条都对应本仓的一个故障题或实测案例。

## 覆盖类

| 症状 | 根因 | 对应练习 |
|---|---|---|
| 整除长度通过，末项为零 | grid 只覆盖了 `N / block` 个块，漏掉尾块 | VA01 |
| 输入增大后结果像只算了一截 | 每线程固定处理一个元素，没有跨步 | RD01 |
| 只有第一段数据被处理 | 只处理了 `blockDim` 范围内的数据 | — |
| 空输入崩溃 | 没有处理 `size == 0` | VA01 扩展 |

**修法**：网格覆盖用 `ceil(N / block)`，线程内做边界判断。

## 归约类

| 症状 | 根因 | 对应练习 |
|---|---|---|
| 全负数的 max 返回 0 | 中性值用 `0` 而不是 `-inf` | RD02 |
| 5 个相同值的平均值不等于它们 | padding 元素贡献了 0 但被计入分母 | RD03 |
| 换成非 2 的幂后树形归约漏项 | 算法假设了 2 的幂 | RD04 |
| 线程数变化导致结果变化 | 统计合并没有带 count | LN01 |
| 平均值在多层合并后偏移 | “均值的均值”，没有按权重合并 | LN01 |

**修法**：中性值按归约类型区分；padding 元素要用**单位元**且**不计入计数**；跨块统计合并用 Welford 并行公式 `M2 + delta²·nA·nB/n`。

## 索引与布局类

| 症状 | 根因 | 对应练习 |
|---|---|---|
| 连续输入正常，切片失败 | 忽略了 stride，假设了连续 | VA02 |
| 广播后不同列异常 | 广播维度的源地址推进算错 | VA03 |
| 4 元素向量化后丢尾部 | 向量化路径没有覆盖非整除尾块 | VA04 |
| 转置后访问变慢 | 列访问不合并 | — |

**修法**：地址推导写成公式；广播维度不推进源地址；向量化必须配尾块路径。

## 同步类

| 症状 | 根因 | 对应练习 |
|---|---|---|
| 输出越界线程退出后合法输出也错 | 提前 `return` 的线程没参与 `__syncthreads()` | GM01 |
| 结果偶尔正确、偶尔错误 | 读 shared memory 前没有屏障 | GM01 |
| 归约结果被下一次调用覆盖 | 返回前没有确认所有读取完成 | 见 `block_reduce` 的尾部屏障 |

**修法**：屏障必须**所有线程**都到达。提前退出的线程要么不退出、要么不参与共享协作。屏障的位置要覆盖“最后写入”和“最后读取”两端。

## 数值类

| 症状 | 根因 | 对应练习 |
|---|---|---|
| 普通负值正常，极负值 NaN | 没做平移，`exp` 溢出 | SM01 |
| 结果和框架对不上 | 累加 dtype 不一致 | — |
| 长归约误差超容差 | 串行累加误差累积 | — |
| 每次运行结果微不同 | 原子加或非确定归约顺序 | — |
| fp16 下大值变 inf | 动态范围不足 | — |

**修法**：softmax 减最大值；累加器提升到 fp32；长归约用树形；契约里登记确定性。

## 注意力类

| 症状 | 根因 | 对应练习 |
|---|---|---|
| 输出超出可见 V 的范围 | online 重缩放没有同步更新 m/l/o | AT01 |
| decode 时只看见第一个 key | 把矩形 attention 的 mask 当左上三角 | 模型切片 |
| 前缀处理后后缀不一致 | RoPE position 没从已有长度开始 | 模型切片 |
| 缓存里旧 K 被重复旋转 | 旋转没有跳过已缓存部分 | 模型切片 |

**修法**：online 状态 `m/l/o` 三者必须一起更新；mask 按**绝对位置**比较；旋转只作用于新增 token。

## 性能类

| 症状 | 先怀疑 |
|---|---|
| 有效带宽只有峰值两成 | 访存不合并、strided 访问 |
| occupancy 高但很慢 | 数据复用不足；或已到带宽上限 |
| 单 kernel 快、整体慢 | kernel 间空隙、启动开销、中间结果落内存 |
| 优化了整体没变 | Amdahl：该阶段占比小 |
| profiler 里的时间比实际大很多 | 插桩开销，不是真实耗时 |
| 区间重叠仍宣布变快 | 统计上分不出差异 |

**修法**：见[流程阶段五](../01-workflow/05-locate.md)和[阶段八](../01-workflow/08-verify.md)。

## 最容易犯的三类

1. **只测典型输入。** 上面每一类里，边界版本都比典型版本多。
2. **拿一次数字当结论。** 性能结论需要区间。
3. **改完不回归。** 优化引入的 bug 基本都落在边界上，而边界以前没过。
