# 故障复盘：从“过了测试”到“说得清原因”

这是完成练习后的讲解，建议先看症状、自己修 student.py，再读本页。参考解往往使用最直白的公式恢复语义；它不等于已完成 GPU 优化。每题最后的扩展输入由你补到 cases.py，再证明修复仍成立。

## VA01：有边界检查，为什么还会少算？

N=5、block=4 时，n//block 只启动一个 block，对应全局线程 0、1、2、3。合法的元素 4 根本没有对应线程。即使每个已启动线程都有 i<n 检查，也无法补出没被启动的线程。

修复分成两个不同职责：向上取整负责覆盖，i<n 负责阻止多出来的线程越界。向上取整后有 8 个线程，前 5 个写结果，后 3 个不访问数组。

手算：a=[1,2,3,4,5]、b 全为 10，错误结果末项为 0，正确结果为 [11,12,13,14,15]。再试 N=0、N=1、N=4、N=8，分别检查无任务、比 block 小、恰好一块、恰好两块。真实 CUDA 对 N=0 应走 host 空输入策略，而不是启动大小为 0 的 grid。

扩展：把 block 改成 3，使用 N=7。解释为什么改 block 不应改变算子语义。

## VA02：逻辑长度相同，物理地址不同

物理 a=[1,99,2,99,3,99]，逻辑视图只包含 [1,2,3]。逻辑下标 i 对应物理位置 i*2。错误实现读取物理前 3 个值 [1,99,2]，再与 b=[10,20,30] 相加，所以第一个元素恰好正确，后面开始错。

stride=1 能掩盖问题；全零或相同数值的底层存储也可能掩盖。测试故意在非视图位置放 99，而不是重复正常值。

修复必须按契约读取逻辑元素，或在接口处明确拒绝非连续输入。这道题要求支持给定的正 stride，所以不能通过偷偷改成拒绝来过关。

扩展：stride=3，让相邻逻辑元素之间的两个位置填不同哨兵值。offset、负 stride 和 alias 不在本题模型中；要支持它们需扩展接口，不能声称本题通过就支持任意张量视图。

## VA03：广播不是随便挑一个坐标

输入是 2×3，bias 长度 3，正确公式为 y[r,c]=x[r,c]+bias[c]。错误代码用 bias[r]，导致整行加同一个数。

第一行 [1,2,3] 应变成 [11,22,33]，不是 [11,12,13]。第二行应为 [14,25,36]。如果 bias 所有元素相同，错误实现也会通过，所以这里必须使用不同 bias。

扩展：用 3×2 输入。错误实现可能直接索引越界，说明“没崩溃”不是证明广播正确的充分条件。回到模型中的投影 epilogue，明确 bias 绑定哪个输出维度。

## VA04：向量路径要留下合法的尾部路径

N=10 时只能形成两个完整的四元素片段：0–3、4–7。只遍历这两片会漏掉 8、9。修复可以处理整片后追加标量尾部，也可以使用真正支持逐元素掩码的合法加载方式。

这里模拟的是漏算，不会在 Python 中模拟越界的 float4 读。真实 CUDA 中还必须先检查四个元素全部合法、地址满足对齐，再发起向量加载；不能“先读四个，再用 if 决定是否消费”。

扩展：N=4q+r，分别覆盖 r=0、1、2、3。再做 [R3 代码阅读题](../reading/README.md)，把长度合法性和地址对齐分开检查。

## RD01：归约树正确，不代表所有数据进入了树

输入 1 到 9，threads=4。只读 x[0:4] 得到 10，而完整结果是 45。树只能合并已经装入的值，不能自动发现未读的尾部。

让线程 t 处理 t、t+threads、t+2*threads 等合法位置。本题四个局部和分别为 1+5+9=15、2+6=8、3+7=10、4+8=12，合并为 45。

扩展：threads=8、N=33，全为 1，正确结果必须是 33。这能同时检查整段之外的多轮循环和最后一项。

## RD02：归约中性值来自运算，不来自习惯

max([-5,-2,-9])=-2。补到长度 4 后若填 0，变成 max([-5,-2,-9,0])=0。Sum 的中性值 0 不能照搬给 Max；有限输入的 Max 可用负无穷作为补齐值。

N 恰为 2 的幂时没有 padding，正数里存在比 0 大的值时也可能看不出错误。这就是必须把“全负”和“非整除”组合测试的原因。

扩展：全为同一个负数、包含真实 0。空输入的 Max 需要单独约定返回/报错规则，本题限定非空；不要不加说明地沿用 Sum(empty)=0。

## RD03：物理容量不能进入 mean 的分母

五个 2 的 sum 是 10。补齐到 8 个位置后，Sum 可让 padding 贡献 0，但 mean 的有效计数仍是 5。错误结果 10/8=1.25，正确结果 10/5=2。

修复可以直接保存有效长度，也可以同时归约 value 与 valid_count。以后处理 ragged batch、masked normalization 时，count 往往不能只从分配容量取得。

扩展：所有有效值相同，改变 padding 宽度；mean 必须不变。这是比一批随机输入更容易手算的性质测试。

## RD04：奇数个 partial 的去向

对 [1,2,3,4,5]，原始 step=2：partial[0]=1+3=4，partial[1]=2+4=6；最后的 5 没参与。再 step=1 得到 10，少了 5。

一种修复是补齐到 8 并填 Sum 的中性值；另一种是每层两两合并，奇数末项原样进入下一层。后者第一次得到 [3,7,5]，第二次 [10,5]，第三次 [15]。

注意两种树的加法顺序不同，一般浮点输入不应要求 bitwise 相同。扩展：长度 3、6、7、9，并加入正负混合数据；设备实现还要检查 shared 范围和每层同步。

## SM01：padding 没进分母，也能破坏稳定性

本题已把无效位置的指数值排除；问题是 max 的初始 0 改变了稳定计算的基准。对于 [-1000,-1001]，错误基准为 0，两个 exp 都下溢到 0，最终成为 0/0。

正确基准为 -1000，平移后 [0,-1]，指数为 [1,0.367879…]，结果约 [0.7310586,0.2689414]。在精确实数运算中减去任意常数仍可等价，但有限浮点数中不等于具有相同稳定性。

普通负数 [-5,-4,-3] 往往仍正常，所以不能把“全负就必错”当作结论。扩展：给一组 logits 同时加上 -1000，再检查概率是否近似不变。

## LN01：局部均值的平均，一般不是整体均值

输入 [1,2,3,4,100] 分给 4 个线程，局部分组为 [1,100]、[2]、[3]、[4]。局部均值为 50.5、2、3、4，直接平均得到 14.875；真实整体均值是 110/5=22。

必须带上 count：全局 mean=(2*50.5+1*2+1*3+1*4)/5。Welford 进一步合并方差时还需要 M2 与均值差带来的修正项，不能只把局部 M2 相加。本题只判均值合并，不声称覆盖完整 Welford 方差。

扩展：同一输入改变线程数。数学结果应在浮点容差内不变；若每个线程恰好同样多元素，错误平均也可能偶然正确。

## GM01：没有输出的线程，可能仍然负责加载

安全模拟取 A 的一行 [1,2,3] 与 B 的一列 [7,9,11]，正确点积是 7+18+33=58。tile 里一个线程的输出列越界，但它承担 A 中间值 2 的搬运；若它提前退出，合法输出缺少这一项，得到 40。

这里模拟将缺失装载当作 0，只为隔离索引问题。真实 shared 内容可能未初始化，且分歧退出还可能破坏同步契约；设备结果不保证恰好是 40。

修复分开三个条件：输入装载是否合法、所有协作线程是否参加同步、最终输出是否合法。越界输入补中性值，最终写回才按输出坐标掩码。扩展：改变缺失乘积为 0，会再次掩盖错误，所以必须保留非零反例。

## AT01：Online Attention 有两个旧状态需要换基准

scores=[0,2]、values=[10,20]。第一步 m=0、l=1、acc=10。第二步最大值变成 2，旧状态缩放 alpha=exp(-2)≈0.135335，新的指数权重为 1。

正确更新为 l=alpha*1+1，acc=alpha*10+20，最终 acc/l≈18.80797。错误更新只缩放 l，acc 却用 10+20，得到约 26.4239，甚至超出可见 V 的 [10,20] 范围。

概率加权平均应在有限标量 V 的最小/最大值之间，这是一个有用的快速诊断性质，但它不是充分的正确性证明。新最大值不增长时 alpha=1，错误会被掩盖。

扩展：分块顺序变化，或比较一次处理与多个块处理；结果应在容差内一致。把这个不变量带到 [模型切片](../../06-model-slice/README.md)，但注意本题不测试其 KV Cache 或 causal mask。

## 修复报告怎么写

不要只写“添加 mask 后修复”。至少给出：一个最小输入、错误的中间值、正确不变量、具体修改、原回归结果、自己新增的一组反例，以及尚未验证的设备条件。GPU 同步问题还需真实 sanitizer；Python 数值正确不证明没有竞争。
